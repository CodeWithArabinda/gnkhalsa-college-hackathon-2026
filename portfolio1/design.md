# Portfolio Redesign & Modification System

## 1. Project Purpose

This project starts with an existing portfolio website cloned from a GitHub repository.

The goal is **NOT to simply change some text and keep the original design**.

The goal is to:

- Analyze the existing portfolio structure
- Preserve useful functionality
- Identify weak or generic design choices
- Redesign the visual system
- Change the color palette
- Improve typography
- Improve spacing and hierarchy
- Modify layouts where necessary
- Add purposeful animations
- Make the final portfolio feel visually distinct from the original repository
- Maintain good performance and responsiveness

The final website should look like a **new portfolio inspired by the existing structure**, not like a recolored clone.

---

# 2. Core Design Philosophy

The portfolio should feel:

- Modern
- Premium
- Personal
- Creative
- Clean
- Interactive
- Professional
- Developer-focused

Avoid making the website feel like:

- A generic SaaS landing page
- A template with only text changed
- A collection of random animations
- An over-designed cyberpunk interface
- A heavy UI with excessive gradients
- A website where every section looks identical

The website should have a clear visual identity.

---

# 3. Existing Repository Modification Rules

Before changing the project:

1. Analyze the existing component structure.
2. Identify reusable components.
3. Identify the existing routing and data flow.
4. Identify the current styling system.
5. Preserve working functionality unless redesigning it provides a clear improvement.
6. Do not unnecessarily rewrite the entire project.
7. Modify the existing code incrementally.
8. Keep the codebase clean and maintainable.

Important:

> Do not change technology or rewrite working architecture unless necessary.

The objective is:

Existing Repository
        ↓
Analyze
